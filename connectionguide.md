## Почему нужен HTTPS

PWA-возможности в Chrome требуют защищённого контекста:
- установка на домашний экран (`beforeinstallprompt`, манифест);
- service worker (офлайн-режим);
- Screen Wake Lock (экран не гаснет).

Локально `http://127.0.0.1` считается защищённым, поэтому на компьютере всё работает и без HTTPS.

## Данные на устройстве

| Что | Где | Ключ |
|---|---|---|
| Видео (Blob), упражнения, тренировки | IndexedDB | база `trenka`, хранилища `videos`, `exercises`, `workouts` |
| Настройки (звук, вибрация, подготовка, mute видео) | localStorage | `trenka.settings` |
| Оболочка приложения для офлайна | Cache Storage | `trenka-v<версия>` (см. `sw.js`) |

Приложение просит `navigator.storage.persist()`, чтобы браузер не удалил видео при нехватке места. Текущий объём показывается в «Видео» и «Настройках».

## Переменные окружения

Для приложения — нет. Для сквозного теста (`npm run e2e`):

| Имя | Назначение | По умолчанию |
|---|---|---|
| `CHROME_PATH` | путь к chrome.exe | `C:/Program Files/Google/Chrome/Application/chrome.exe` |
| `E2E_PORT` | порт локального статического сервера | `8765` |

## Инструменты разработки

- Node 25+ (unit-тесты через `node --test`, e2e через puppeteer-core).
- Chrome (рендер PNG-иконок, e2e).
- ffmpeg (генерация тестового видео для e2e).
- Python 3 — только как локальный статический сервер (`py -m http.server`).
